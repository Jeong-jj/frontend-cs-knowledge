## 이 프로젝트가 하려는 것

프론트엔드 면접에서는 프레임워크 사용법보다 그 아래에서 벌어지는 일을 묻는다.
브라우저가 화면을 그리는 순서, HTTP 캐시가 동작하는 조건, 이벤트 루프가 콜백을
꺼내는 규칙 같은 것이다. 실무에서는 이 층을 정의 수준으로만 알고 넘어가기 쉽고,
그 상태로는 첫 질문에 답해도 두 번째 꼬리 질문에서 막힌다.

이 저장소는 그 층을 근본부터 다시 훑어 **설명할 수 있는 상태**로 만드는 것을 목표로 한다.
개념 정리에서 멈추지 않는다.

```text
개념 정리 노트     개념의 기초 설명과 심화 내용
면접 대비 문서     개념 정리 + 예상 질의응답 + 실무 적용 + 면접 연습 방식
```

이 저장소는 후자다. 각 문서는 하나의 질문에 답하고, 그 답을 30초·2분·심화
세 길이로 말할 수 있는 형태까지 정리한다.

### 다루는 범위

CS 전 영역을 전공 과정처럼 훑지 않는다. 프론트엔드 실무와 면접에서 활용도가 높은
영역을 우선한다. 브라우저, HTTP, DNS/TCP/TLS, JavaScript 런타임, 웹 보안, 웹 성능,
그리고 이들을 설명하는 데 필요한 만큼의 OS 기초다.

### 관문 질문

이 저장소가 최종적으로 답하려는 질문은 하나다.

> 브라우저 주소창에 `https://example.com` 을 입력하고 화면이 표시되기까지 무슨 일이 일어나는가?

각 단계를 이유와 함께 이을 수 있어야 한다.

```text
URL 해석 → DNS 조회 → IP 확인 → TCP 연결 → TLS 핸드셰이크
→ HTTP 요청과 응답 → HTML 파싱과 리소스 로딩 → DOM/CSSOM 생성
→ JavaScript 실행 → Render Tree → Layout → Paint → Composite
```

## 학습 원칙

### 프론트엔드에서 출발해 기반 기술로 내려간다

네트워크 계층이나 운영체제 이론부터 시작하지 않는다. 매일 쓰는 브라우저에서 출발해
HTTP, TCP/TLS, JavaScript 런타임, 운영체제로 범위를 넓힌다.

### 정의보다 인과관계를 다룬다

각 주제는 다음 질문에 답할 수 있을 때까지 파고든다.

- 이것은 무엇인가
- 왜 필요한가
- 내부에서 어떤 순서로 동작하는가
- 다른 개념과 어떻게 연결되는가
- 프론트엔드에서 언제 관찰되는가
- 잘못 쓰거나 실패하면 어떤 문제가 생기는가
- 30초, 2분, 심화 답변으로 각각 어떻게 설명하는가

### 읽은 것으로 끝내지 않는다

이해한 느낌은 검증되지 않은 상태다. 자기 말로 설명하고, 예시를 만들고,
꼬리 질문을 받은 뒤 문서를 고친다.

### 문서는 결과물이자 학습 도구다

받아 적는 노트가 아니다. 질문, 수정된 설명, 실무 사례, 꼬리 질문이 쌓이는
살아 있는 자료다. 다만 **과정은 문서에 남기지 않는다.** 문서는 도달한 이해의
현재 상태만 담고, 과정은 `sessions/` 가 맡는다.

## 로드맵을 이 순서로 짠 이유

```text
브라우저 → HTTP → DNS/TCP/TLS → JavaScript 런타임 → 웹 보안 → 웹 성능
→ OS 기초 → 통합 면접 훈련
```

1. **브라우저가 중심축이다.** 렌더링, 네트워크 요청, JavaScript 실행, 보안 정책,
   캐시와 성능이 모두 브라우저에서 만난다.
2. **HTTP 는 프론트엔드와 서버가 실제로 대화하는 규칙이다.** 상태 코드, 헤더, 쿠키,
   캐시는 일상적인 개발 경험과 바로 이어진다.
3. **DNS, TCP, TLS 는 HTTP 아래에서 벌어지는 일을 설명한다.** 이 층을 알아야 연결 지연,
   신뢰성, HTTPS, 인증서, 핸드셰이크 비용을 설명할 수 있다.
4. **JavaScript 런타임은 비동기 코드의 실제 실행을 설명한다.** Call Stack, Task Queue,
   Microtask Queue, Event Loop 는 Promise 와 타이머와 렌더링의 순서를 가르는 기반이다.
5. **웹 보안은 앞의 지식을 전제로 한다.** SOP, CORS, XSS, CSRF, 쿠키 속성은 출처와 요청과
   인증 상태를 이해해야 암기가 아닌 원리로 설명된다.
6. **웹 성능은 여러 영역을 통합하는 응용 주제다.** 네트워크, 캐시, 렌더링, JavaScript
   실행 비용을 함께 판단해야 한다.
7. **OS 는 필요한 만큼 뒤에서 보강한다.** 프로세스, 스레드, 메모리를 브라우저 멀티프로세스
   구조와 JavaScript 실행에 붙이면 학습 효율이 높다.
8. **마지막에 지식을 답변으로 바꾼다.** 아는 것과 제한 시간 안에 설명하는 것은 별개다.

## 6주 로드맵

주당 8~9시간(평일 1시간, 주말 3~4시간)을 기준으로 한 **1회독 계획**이다.
복습 회차는 각자의 진도에 맞춰 `sessions/` 에 쌓는다.

진도보다 설명 가능 여부를 우선하되, 한 주의 산출물을 끝내고 다음으로 넘어간다.

| 요일 | 하는 일 |
|---|---|
| 월 | 현재 이해 진단, 전체 흐름 파악 |
| 화·수 | 핵심 개념 학습 |
| 목 | 코드나 개발자도구로 재현 |
| 금 | 면접 답변 작성과 꼬리 질문 |
| 주말 | 문서 완성, 누적 복습, 통합 설명 연습 |

## 한 주제를 학습하는 방법

### 1. 현재 이해 확인

대표 질문 2~3개를 먼저 받는다. **검색하거나 자료를 보기 전에** 아는 만큼 답한다.
이 답변은 출발점이지 평가가 아니다. `sessions/` 에 그대로 남긴다.

### 2. 개념 학습

전체 흐름을 먼저 보고 각 단계로 들어간다.

```text
현상 또는 문제 → 개념의 목적 → 내부 동작 → 코드나 네트워크 예시
→ 실무에서의 관찰 지점 → 흔한 오해
```

### 3. 재현

개발자도구나 짧은 코드로 직접 확인한다.

- Network 패널에서 요청과 캐시 상태 관찰
- Performance 패널에서 렌더링과 Long Task 확인
- `async` 와 `defer` 실행 순서 비교
- Promise 와 타이머의 실행 순서 예측 후 검증
- CORS preflight 요청 확인

확인한 절차는 문서의 `직접 재현하기` 에 독자가 따라 할 수 있게 옮긴다.

### 4. 자기 말로 설명

세 길이로 답한다.

- **30초** — 핵심 정의와 목적
- **2분** — 동작 순서와 대표 사례
- **심화** — 예외, 트레이드오프, 관련 개념까지 확장

### 5. 꼬리 질문

답변의 키워드를 근거로 3~5개를 받는다. 막힌 것은 TODO 로 남긴다.

### 6. 문서화와 복습

문서에 반영하고, 다음 복습 때는 문서를 보지 않고 다시 설명한다.
틀린 부분과 새로 이해한 것을 문서에 누적 갱신한다.

## 세션 운영

### 시작

- 오늘 다룰 주제
- 이전 학습 중 연결되는 개념
- 지금 설명할 수 있는 범위
- 이번 세션의 완료 기준

### 진행

진단 질문 → 답변 → **맞은 것·빠진 것·잘못된 것**으로 나눈 피드백 → 원리와 전체 흐름 설명
→ 재현 → 면접형 질문과 꼬리 질문 → 문서 반영

### 종료

- 오늘 이해한 핵심 3~5개
- 아직 모호한 지점
- 면접에서 쓸 표준 답변
- 다음 세션 항목
- 생성하거나 수정할 문서 경로

### 스킬

| 스킬 | 하는 일 |
|---|---|
| `/study` | 세션 시작. 진도 확인 후 진단 질문 |

## 문서 규칙

### 파일명

폴더와 파일명은 소문자 kebab-case 를 쓴다. 한 문서는 하나의 중심 질문을 다룬다.
길어지면 하위 주제로 나누고 서로 링크한다. 시간이 아니라 주제로 분류한다.

### 템플릿

`docs/document-template.md` 를 쓴다. 기초와 심화를 나누고, 예상 질문에는
30초·2분·심화 답변을 모두 채운다.

### 작성 원칙

`CLAUDE.md` 의 「문서 작성 원칙」 을 따른다. 핵심은 셋이다.

- 독자는 이 저장소를 처음 보는 프론트엔드 개발자다
- 정의만 나열하지 않고 원인과 결과를 잇는다
- 학습 과정과 감상은 문서가 아니라 `sessions/` 에 남긴다

### README

루트 `README.md` 에는 프로젝트 목적, 로드맵, 문서 링크, 문서별 완성 상태,
저장소 사용법, 통합 질문 목록을 유지한다.

## 완료 기준

6주를 소화하는 것으로 완료를 판단하지 않는다.

- URL 입력부터 렌더링까지 전체 흐름을 5분 안에 설명한다
- 각 영역에서 대표 질문 5개 이상에 자기 말로 답한다
- 답변에 정의, 목적, 동작 순서, 실무 사례가 들어간다
- 주요 질문에 2~3단계 꼬리 질문까지 대응한다
- 개발자도구로 네트워크, 캐시, 렌더링, 성능 현상을 직접 확인한다
- 실제 프로젝트 경험 3개 이상을 CS 개념과 연결해 설명한다
- 모든 문서가 README 에서 링크되고 검색 가능한 구조로 정리된다
- 취약 개념과 후속 학습 항목이 목록으로 남는다
