# 복습과 모의 면접

**이것은 학습이 아니라 검증이다.** 설명을 먼저 하면 검증이 아니게 된다.

## 1. 대상을 고른다

인자가 있으면 그것을 쓴다. 없으면 `sessions/progress.md` 에서 고른다.

우선순위는 **막힌 횟수가 높은 것 → 마지막 복습이 오래된 것 → 최근 학습한 것** 순이다.
「막힌 지점」 은 주제보다 잘게 쪼개져 있으므로 여기부터 본다.

인자가 `mock` 이면 통합 모의 면접으로 간다. 아래 5번이다.

## 2. 문서를 보여주지 않는다

**학습자에게 해당 문서를 열지 말라고 먼저 말한다.**
보고 답하면 인출 연습이 되지 않고, 아는 느낌만 남는다.

## 3. 길이를 올려 가며 묻는다

한 번에 하나씩 묻고 답을 받은 뒤 다음으로 간다.

```text
30초  핵심 정의와 목적
2분   동작 순서와 대표 사례
심화  예외, 트레이드오프, 관련 개념
```

**막히면 답을 주지 않는다.** 어디까지 왔는지 확인하고 그 지점을 기록한다.

## 4. 꼬리 질문 3~5개

학습자가 쓴 키워드를 근거로 만든다. 문서에 없는 각도를 하나는 섞는다.
면접은 첫 답변이 아니라 여기서 갈린다.

## 5. 모의 면접일 때

`README.md` 의 통합 면접 질문에서 하나를 고른다.
주제를 가로지르게 묻고, 답변 시간을 잰다. 목표는 5분 안이다.

```text
질문 → 답변 → 시간 기록 → 꼬리 질문 2~3단 → 채점
```

## 6. 채점한다

**맞은 것 / 빠진 것 / 잘못된 것** 으로 나눈다. 총평 대신 항목으로 적는다.
잘못된 것은 무엇이 틀렸는지와 왜 그렇게 오해하기 쉬운지까지 말한다.

## 7. 반영을 제안한다

기록은 승인을 받고 한다 (`CLAUDE.md` 「기록 규칙」). 무엇을 어디에 쓸지 밝힌다.

- `sessions/progress.md` — 마지막 복습일(`yy-mm-dd`), 막힌 횟수, 막힌 지점, 다음 복습 대상
- 오늘 세션 파일 — 막힌 지점과 꼬리 질문 대응

**막힌 것이 문서 탓인지 내 탓인지 가른다.**

```text
문서에는 제대로 있는데 못 말했다   → 막힌 지점.  내가 복습할 몫
문서를 봐도 안 나온다            → 문서에서 발견한 결함.  PR 대상
```

막힌 횟수는 **회차를 넘어 누적한다.** 리셋하지 않는다.
복습 간격은 이 값에 따라 좁힌다. 0회면 넉넉히, 두 번 이상 막혔으면 며칠 안에 다시 본다.
