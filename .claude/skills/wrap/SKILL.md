# 정리

## 1. 무엇을 어디에 쓸지 먼저 말한다

목록으로 제시하고 승인을 받는다. 승인 없이 파일을 고치지 않는다.

> - `01-browser/rendering-pipeline.md` — 기초 절에 DOM/CSSOM 생성 순서, 심화 절에 parser-blocking 조건
> - `sessions/2026-09-08-browser.md` — 진단 답변, 꼬리 질문 3개, 막힌 지점 1개
> - `glossary.md` — CSSOM, Render Tree
> - `sessions/progress.md` — 렌더링 파이프라인 상태를 학습중으로

## 2. 학습 기록과 문서 수정을 가른다

**이 구분이 이 저장소 구조의 기둥이다.** 섞으면 문서가 다시 개인 노트가 된다.

```text
"이 부분 설명이 막혔다"      → sessions/ 의 막힌 지점.  문서는 고치지 않는다
"문서에 이 내용이 아예 없다"  → 문서 보강.  PR 대상
"문서의 이 설명이 틀렸다"    → 문서 교정.  PR 대상
```

앞은 **내 문제**고 뒤의 둘은 **문서의 문제**다.
문서를 고치는 기준은 학습을 진행했는지가 아니라 **문서에 결함이 있는지**다.

## 3. 학습 문서를 고친다

문서가 비어 있으면 새로 쓰고, 채워져 있으면 2번에서 가른 결함만 고친다.

`docs/document-template.md` 의 절 구조를 유지한다. 절을 지우지 않고, 비면 `없음` 을 남긴다.

- **기초와 심화를 섞지 않는다.** 개념이 성립하는 데 필요한 것만 기초에 둔다
- 예상 질문에는 30초·2분·심화를 **모두** 채운다. 하나라도 비면 길이 조절 연습이 안 된다
- 재현 절차는 독자가 그대로 따라 할 수 있게 쓴다
- 확실하지 않은 것은 본문에 단정해 넣지 말고 `검증 TODO` 로 내린다
- **학습 과정과 감상을 본문에 남기지 않는다.** 그것은 세션 기록으로 간다

### push 권한이 없으면

```bash
git remote -v
gh repo view --json viewerCanAdminister 2>/dev/null
```

원본 저장소에 권한이 없으면 문서 수정은 **fork 후 PR** 로 올린다.
`.github/pull_request_template.md` 를 그대로 쓴다. PR 에는 학습 과정이 아니라
**문서의 어디가 틀렸고 근거가 무엇인지**를 쓴다.

자기 것으로 다시 쓰고 싶으면 fork 해서 자기 저장소에서 한다.
`sessions/` 는 진도와 세션 기록 전용이다. 여기에 문서 사본을 만들지 않는다.

## 4. 세션 기록에 이어 쓴다

`sessions/` 의 오늘 파일에 append 한다. 덮어쓰지 않는다.
진단 답변은 다듬지 않고 원문 그대로 둔다. 나중 복습의 기준선이 된다.

## 5. 용어를 넣는다

이번에 처음 나온 용어를 `glossary.md` 의 해당 절에 넣는다.

```text
- **CSSOM** (CSS Object Model) — CSS 를 파싱해 만든 트리. Render Tree 의 한쪽 입력이다. → [렌더링 파이프라인](01-browser/rendering-pipeline.md)
```

한 문장으로 못 쓰면 그 용어는 여기 있을 것이 아니라 문서에서 다룰 것이다.

## 6. 진행 상태를 갱신한다

`sessions/progress.md` 를 고친다. 날짜는 `yy-mm-dd` 로 쓴다.

- **상태** — 대화를 통한 학습 진도다. 문서를 만들었는지가 아니다.
  주제를 끝냈으면 `학습완료`, 진행 중이면 `학습중`
- **완료 회차** — 이번 회차에 그 주제를 끝냈으면 1 올린다
- **막힌 횟수** — `/drill` 이 갱신한다. 여기서는 건드리지 않는다
- **막힌 지점** — 2번에서 가른 것 중 내 몫
- **문서에서 발견한 결함** — 2번에서 가른 것 중 문서 몫. PR 로 처리했으면 지운다

## 7. README 를 본다

문서 상태가 바뀌었으면 `README.md` 의 문서 표를 고친다.
새 문서를 만들었으면 표에 줄을 추가한다. **README 에서 링크되지 않는 문서는 없어야 한다.**

`README.md` 는 문서 완성 상태를, `sessions/progress.md` 는 학습 진도를 들고 있다.
**두 곳에 같은 것을 적지 않는다.**
